B9. Negative test — try a cert that's NOT in the allow-list
Quick way to prove allow-list enforcement (not just CA trust):

HTTP status 403. ✅ Server accepted the TLS handshake (CA trust valid) but rejected the request (identity not allow-listed). That's the precise behavior the PS requires for payments clients.

If anything doesn't match the expected output above, paste me the actual response and I'll debug it. The most common gotchas:

Wrong directory — make sure you're in the upgraded datashield/ from the zip, not a previous version
mTLS port confusion — when enabled: true, the API binds :8443 not :8000
curl -k won't work for client-cert tests — -k skips server cert verification but you still need --cert/--key for the client side
Browser at https://localhost:8443/docs — browsers won't send a client cert by default; use curl for testing, or import the client cert into your browser's keystore
